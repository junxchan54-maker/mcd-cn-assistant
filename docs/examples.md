# 使用示例

以下示例展示 `mcd-cn-assistant` 在真实对话中的行为，含**用户说什么**与**Agent 应该做什么**。

---

## 能力一 · 最新活动推送

### 示例 1：月度活动概览

**用户**：这个月麦当劳有什么活动？

**Agent 行为**：
1. 调用 `now-time-info` 取得当前日期；
2. 调用 `campaign-calendar` 拉取当月营销活动日历（返回进行中 / 往期 / 未来）；
3. 按「进行中 → 即将开始」分组输出，**略过往期**；
4. 每条包含：活动名、起止时间、一句话参与方式、入口。

**输出示例**：

```
🍟 麦当劳 2026 年 10 月活动速览

【进行中】
· 麦麦省周三会员日        10/01 - 10/31   每周三登录领专属券
· 早餐卡限时 5 折         10/05 - 10/20   随单购买早餐卡享 30 天早餐 5 折

【即将开始】
· 新品上市（待公布）       10/15 起        关注官方渠道

👉 需要我盯着某个关键词，有活动就自动提醒你吗？
```

## 能力二 · 联名活动关注推送

### 示例 2：新增关注关键词

**用户**：帮我盯着联名款，有新的就推给我

**Agent 行为**：
1. 读取 `config/keywords.json`；
2. 把 `联名` 追加进 `follow_keywords`（去重）；
3. 同时扩展同义词表：`联动 / 限定 / 合作款 / 联名款 / IP合作 / 品牌合作 / co-brand`；
4. 更新 `updated_at`，写回文件；
5. 回显最新列表确认。

**输出示例**：

```
已更新关注关键词 ✅

当前关注：联名
同义匹配：合作款、联名款、IP合作、品牌合作
推送时间：每天 09:00

之后每月活动日历中只要出现上述关键词，我会主动推给你。
```

### 示例 3：定时推送

**触发**：每天 09:00 的自动化任务（只读，不执行任何写操作）

**输出示例**：

```
🎉 麦当劳活动关注推送 | 2026-10-12
命中关键词：联名

【进行中】
· 与 XXX 联名周边限定套餐   10/10 - 10/31
  购买指定套餐得联名限量周边，全国门店参与

【即将开始】
· 联名新品上线              10/20 起
  联名款汉堡 + 联名包装，敬请期待
```

**无命中时**（不拿无关活动凑数）：

```
🎉 麦当劳活动关注推送 | 2026-10-13
命中关键词：联名

今日无命中关键词「联名」的新活动。
```

### 示例 4：维护关键词

**用户**：不关注联名了，改成关注新品和早餐

**Agent 行为**：更新 `follow_keywords` 为 `["新品", "早餐"]`，回显最新列表。

**用户**：我现在关注了哪些？

**Agent 行为**：读取配置并回显列表 + 同义词 + 推送时间。

## 点餐入口 · 主动询问「单人 / 多人拼单」（能力三 / 四 共用）

### 示例 5：点餐时的入口询问

**用户**：帮我点个麦当劳，中午想吃点好的

**Agent 行为**：

1. 先澄清基本需求（想吃什么 / 预算 / 到店取还是外送）；
2. **在定位门店之前**，主动问一句（这是硬性规则，不能省）：

   > 这单是**你自己一个人**吃，还是**帮几个人一起点（拼单）**？拼单的话我可以代录大家想吃的、帮你凑满减、把配送费和打包费算清楚，最后出一张「每人应付多少」的账单。

3. 按用户的回答分流：

| 用户回答 | 走向 |
|---|---|
| "就我自己" / "一人份" | **能力三 · 最优惠点餐**（示例 6） |
| "我们部门 5 个人一起点" / "拼单" | **能力四 · 多人群点聚合**（示例 10），接着确认人数、门店/地址与分摊偏好 |
| "我们几个人一起吃，但我自己付、不用分摊" | **能力三**按整单找最省组合，顺带问一句"要不要按人出一张分摊账单" |
| "随便点点"（含糊或没表态） | **再确认一次**，**不默认按单人处理** |

**要点**：

- 多人拼单**不依赖用户自己提出**——入口必问，这是能力四最主要的触发路径；
- 用户已在同一句话里说清是多人（"我们 5 个人一起点""办公室下午茶"）时，视为**已回答**，不重复问第二遍；
- 用户已明确单人（"我就想喝杯咖啡"）时，不再提拼单，也不反复推销；
- 入口询问**只问一次**，不要在后续阶段反复确认。

## 能力三 · 最优惠点餐

### 示例 6：到店取餐比价

**用户**：两个人吃，到店取，怎么点最划算？我在静安寺附近（入口询问时已确认："一起吃、我自己付款、不用分摊"）

**Agent 行为（严格按序）**：

1. `now-time-info` 取当前时间；
2. `query-nearby-stores`（地址：静安寺附近）→ 列出候选门店，跟用户确认一家；
3. **盘券**：
   - `available-coupons` 查麦麦省可领券；
   - 若有可领券 → 询问用户是否一键领取 → 同意后 `auto-bind-coupons`；
   - `query-my-coupons` 查账户已有券；
   - `query-store-coupons` 查**该门店**可用券；
4. `query-meals` 拉菜单（含分类、编码、标签、优惠价）；
5. 围绕券的适用条件枚举 2~5 个候选组合（单品券方案 / 满减凑单方案 / 第二份半价方案）；
6. **逐个**调 `calculate-price`（带上所选券）真算金额；
7. 输出比价表，主推应付最低方案。

**输出示例**：

```
📍 门店：麦当劳（静安寺店）  到店取餐

| 方案 | 商品组合 | 使用券 | 商品金额 | 优惠 | 应付 |
|---|---|---|---|---|---|
| ✅ 最省 | 双层牛堡套餐 ×2 | 满 39 减 8 | ¥41.00 | -¥8.00 | **¥33.00** |
| 备选 A | 双层牛堡套餐 ×2 | 第二份半价 | ¥45.50 | -¥7.25 | ¥38.25 |
| 备选 B | 单点组合 | 无 | ¥38.00 | ¥0.00 | ¥38.00 |

💡 最省的方案用的是「满 39 减 8」：两套套餐原价 ¥41 刚好过 ¥39 门槛，
    比「第二份半价」多省 ¥5.25。

要按「✅ 最省」下单吗？回复「下单」我就创建订单。
```

8. 用户说「下单」→ `create-order`；用户不确认则**不下单**。

### 示例 7：外送点餐

**用户**：外卖点个午餐，送到公司

**Agent 行为**：
1. `delivery-query-addresses` 查已保存地址 → 让用户选择；
2. `delivery-query-stores` 查该地址可配送门店；
3. 后续与到店流程一致，但两点不同：① `calculate-price` 结果会**同时包含配送费和打包费**；② **外送菜单价与到店不同**（实测：脆薯饼 到店 ¥8.5 / 外送 ¥9.5；猪柳蛋麦满分 到店 ¥18 / 外送 ¥18.5），必须按 `orderType=2` 重新调 `query-meals` 取价，**不可复用上一轮到店的菜单价**；
4. 比价时把配送费 + 打包费一起纳入应付总额比较。

### 示例 8：只要单品

**用户**：就想吃个麦辣鸡腿堡，怎么买最便宜

**Agent 行为**：退化为「该单品可用券中优惠最大的组合」——查券 → 查价 → 比价 → 给出最优。

### 示例 9：取消订单

**用户**：帮我取消刚才的订单

**Agent 行为**：
1. `order-list` / `query-order` 定位到具体订单；
2. **向用户确认要取消哪一单**；
3. 用户确认后调 `cancel-order`。

## 能力四 · 多人群点聚合

### 示例 10：办公室下午茶拼单（真实实测）

**用户**：办公室下午茶，5 个人拼麦当劳外送到公司，帮我收单算账

**Agent 行为（四阶段）**：

1. **开单**：确认门店 / 地址（`delivery-query-addresses` → `delivery-query-stores`）+ 三项分摊偏好——**公共费用**（配送费 + 打包费）怎么摊（均摊 / 按比例 / 指定人）？券省的钱归你还是平摊？接受凑单建议吗？→ 创建订单会话文件；
2. **收单**：你逐个转述成员报单，Agent 每次增量回显聚合列表：

```
📋 当前群单（4/5 人已报）
· 张三  板烧鸡腿麦满分单人餐×1
· 李四  芝芝火腿扒堡三件套×1
· 王五  猪柳蛋麦满分×1  脆薯饼×1
· 赵六  麦咖啡™冰奶铁中杯×1  香芋派×1
小计 ¥92.70
（本单算价未返回满减档位，无"距下一档"提示）
```

3. **算账**（成员说"收完了"后）：
   - 盘券（下单人账户）：命中「9.9元中杯冰美式」，原价 ¥19.00 → 券后 **¥9.90**（省 ¥9.10），已用 `calculate-price` 实算验证；
   - 券归属：按平摊规则，账单标注「券省 ¥9.10，每人减 ¥1.82」；
   - 公共费用 ¥9.00（配送费 ¥6.00 + 打包费 ¥3.00）按消费比例分摊（尾差兜底，合计严格等于实付）；
   - 凑单判定：`calculate-price` 未返回 `enjoyable`/`balance` → 直接说明"本单无可跨满减档位"，**不臆造档位、不自动加购**；
4. **成单**：输出每人应付账单 → 组织者确认 → `create-order` 单账户结算。

**输出示例（门店 storeCode 1421053，真实数据）**：

```
🧾 麦当劳群点账单 | 2026-10-12 10:05 | 麦当劳深圳金丰城餐厅 · 外送 | 共 5 人

| 成员 | 餐品 | 券前小计 | 分摊券省 | 分摊公共费 | 应付 |
|---|---|---|---|---|---|
| 张三 👑 | 板烧鸡腿麦满分单人餐×1 | ¥21.90 | -¥1.82 | ¥1.76 | **¥21.84** |
| 李四 | 芝芝火腿扒堡三件套×1 | ¥19.90 | -¥1.82 | ¥1.60 | **¥19.68** |
| 王五 | 猪柳蛋麦满分×1，脆薯饼×1 | ¥28.00 | -¥1.82 | ¥2.26 | **¥28.44** |
| 赵六 | 麦咖啡™冰奶铁中杯×1，香芋派×1 | ¥22.90 | -¥1.82 | ¥1.85 | **¥22.93** |
| 钱七 | 麦咖啡™冰美式中杯×1 | ¥19.00 | -¥1.82 | ¥1.53 | **¥18.71** |
| **合计** |  | **¥111.70** | **-¥9.10** | **¥9.00** | **¥111.60** |

💳 券「9.9元中杯冰美式」省 ¥9.10（原价 ¥19.00 → 券后 ¥9.90）：按平摊规则每人减 ¥1.82。
🛵 公共费用 ¥9.00（配送费 ¥6.00 + 打包费 ¥3.00）：按消费比例分摊。
🛒 凑单判定：算价未返回可享受优惠（enjoyable）→ 本单无可跨满减档位，未加购。
💰 收款：请向 👑下单人 张三 支付「应付」列金额（建议微信群收款，逐个按金额）。
✅ 校验：Σ每人应付 ¥111.60 = 实付总额 ¥111.60。

> ⚠️ 两个易错点（实测踩到过）：① 外送单**一定还有打包费**，只分摊配送费会让合计对不上；② 用券成员的"小计"要用**券前基准价**（¥19.00），否则券省被重复扣减，差额恰好等于券省额。

### 示例 11：成员想用自己账户的券

**用户**：我们几个人都有券，能不能各自用自己的券下单？

**Agent 行为**：**明确解释边界**——MCP 是单账户鉴权，本单只能用下单人账户的券统一结算；无法也**不允许**登录他人账户。替代方案：其他成员自行另点，或线下自行折让（在账单备注，不改账单金额）。

## 边界行为（重要）

以下场景技能会**主动刹车**，这是设计红线：

| 场景 | Agent 行为 |
|---|---|
| 用户只说"帮我点个餐"但没确认明细 | 只给方案和报价，**不下单** |
| 点餐请求但没说明几个人 | **先主动问"单人还是多人拼单"**（见示例 5），不得直接按单人往下做；答多人则转入能力四 |
| 用户问"有什么券" | 只查询，**不自动领取**；领取前必须询问 |
| 有券即将过期 | 提示用户，但**不擅自下单用券** |
| 下单前 | 必须列出：门店、商品、规格、单价、优惠、配送费、打包费、应付总额 |
| 任何写操作 | 必须获得用户**明确同意**后才执行 |
| 群点凑单建议 | 只建议不自动加购；必须先实算证明"加购后总支出更低"，再征求确认；无满减档位时直接说明"无凑单空间"，**不臆造档位** |
| 券专享商品算价返回空 | `calculate-price` 返回 `price:0`/`productList` 为空时，判定为"该餐品需带券购买"，**带上对应券重算**，不要误报商品下架 |
| 群点账单合计与实付不符 | 先查两处口径：是否漏了**打包费**；用券成员的"小计"是否误用了券后价（应为**券前基准价**） |
| 成员要求代登他的账号 | **拒绝**：禁止模拟 / 代理登录，只能组织者单账户结算 |
| 生成收款码 | Skill 不代收款项、不生成官方收款码；只产出每人应付账单，收款由组织者完成 |
| **用户要买联名周边** | **能买**（2026-10-16 修正）：周边在 `query-meals` 里，走主链路；加购 `521234` 麦金卡体验卡（¥9.90）通常更省。做不到的是：积分商城换周边、查实时库存 |
| **用户要"监控门店补货"** | **无库存接口、无法持续监控** → 按需扫描目标门店菜单，并说明是"查询时点在售状态"而非实时库存 |
| **用户发小红书链接** | **抓不到内容**（登录墙）→ 引导粘贴文案或发截图，不要反复重试 |
| **隐藏吃法要"多要两包番茄酱"** | 免费配件**不是商品、无法加购** → 外送单写 `remark`（≤50 字）；到店单给到店话术，不得虚构参数 |
| **用户要求"去酱/走酱"** | `modification` 真能做到，按 key 规则传参；但算价接口不回显特调，不得断言"已生效" |
| **用户问天气/下雨推荐** | **无天气数据源** → 可做时段/星期场景推送；天气需用户自述，不编造气温降雨 |
| **晒单卡片数字对不上** | 价格必须来自 `calculate-price`、热量来自 `list-nutrition-foods`；没查过就不写，不编造 |
| **用户要买联名周边（帽/徽章/丝巾）** | **能买**（2026-10-16 修正，推翻 10-13 的错误结论）：周边在 `query-meals` 里，走主链路下单；加购 `521234` 麦金卡体验卡（¥9.90）通常更省。做不到的是：积分商城换周边、查实时库存（见示例 13） |

## 小贴士

- **想省钱**：先让 Agent 跑一次「最优惠点餐」，它会顺带把你该领的券都算进去。
- **想省心**：设置联名关注，每天 09:00 自动收联名 / 限定活动推送。
- **想拼单**：不用先说明——点餐时 Agent 一定会问"单人还是多人"，回一句"我们几个人一起点"就会进入完整的分账流程。
- **想控热量**：可以要求叠加 `list-nutrition-foods`，在比价的同时看营养成分。
- **积分别浪费**：让 Agent 查 `query-my-account` 看积分余额，`mall-points-products` 看能换什么。
- **追联名周边**：让 Agent 盯着联名关键词，开售时点会提前告诉你；周边**可以直接代买**（在菜单里，加购麦金卡体验卡通常更省），但 MCP 没有实时库存接口，只能"问一次扫一次"。
- **想复刻小红书爆款**：直接把文案粘过来或发截图，Agent 会拆出"能加购的单品 / 能改的特调 / 只能备注的免费配件"三类。注意**小红书链接抓不到**，别发链接。
- **减脂期**：报出热量上限和蛋白下限，Agent 会用官方营养表配组合；取消酱料、换无糖饮料都是 +¥0 的真特调。

## 示例 12：联名爱好者全流程（查询 → 追踪 → 购买，真实实测）

**用户（联名粉丝）**：我是麦当劳联名产品的忠实粉丝，最近有什么联名活动？帮我盯着，有新的就告诉我。

**Agent 行为**：`now-time-info` → `campaign-calendar` → 读 `config/keywords.json` → 关键词命中过滤，**只推命中项**，按「进行中 → 即将开始」分组，略过 9.9 元早餐、厚松饼堡、麦咖啡黑巧等非联名活动。

**输出示例**（2026-10-13 实测数据）：

```

命中关键词：联名（同义：联动 / 限定 / 合作款 / 联名款 / IP合作 / 品牌合作）
—— 进行中 ——
· 麦当劳 X PEACEMINUSONE  10-08 10:45 起在售
  GD 同款联名复古棒球帽，任意餐品消费加 39.9 元即可得；APP 专享积分抢先购 10:40
—— 即将开始 ——
· 麦当劳 X PEACEMINUSONE（周边第二弹）  10-15 10:45
  联名徽章一套三枚，任意餐品消费加 39.9 元，APP 抢先购 10:40
· 麦当劳联动 G-DRAGON  10-16
  龙焰鸡腿堡三件套 26.9 元起、韩式风味蘸酱上新

## 示例 18：券 ID 只能从门店券接口拿（2026-10-16 实测）

**用户**：我卡包里那张 9.9 的冰美式，帮我用它算算多少钱。

**Agent 行为**：先 `query-my-coupons` 发现只有标题没有 ID → 改走 `query-store-coupons`：

```
query-my-coupons    → 只返回「9.9元中杯冰美式」标题、有效期、标签
                       ⚠️ 没有 couponId / couponCode，喂不给 calculate-price
query-store-coupons → couponId 264B97DBE02BE6CF996AA6914151C4A9
                      couponCode MCD61G6F07005490G1910
                      适用商品 507411 麦咖啡™冰美式中杯

calculate-price(507411, couponId, couponCode) →
  productOriginalPrice 2300 → price 990
  即 ¥23.00 → ¥9.90
```

**要点**：
- **`query-store-coupons` 是唯一返回 `couponId`/`couponCode` 的接口**，带券算价必须先走它；附带还能拿到 `products[].productCode`，顺手知道券适用哪些商品。
- **`discount` 字段别直接当"省了多少"**：此处 `discount: 1310` 是相对券原价 ¥23.00 算的，而菜单促销价本是 ¥11.90。向用户解释用"日常价 → 券价"，别报 `discount`。
- 券有渠道与时段限制（该券标签含"今日到期、到店专用、外送专用"），用前先看有效期。
