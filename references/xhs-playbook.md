# 小红书场景打法手册（xhs-playbook）

配套 `SKILL.md` 第 8 节（能力五 ~ 十）。本文件提供**可直接执行的词典、算法与模板**；所有商品编码、价格、营养数字均来自 **2026-10-16 对线上 MCP 的实测**，标注了门店与渠道。

> **使用前必读**：编码与价格**随门店和渠道变化**。表中编码是"实测样本"，用于说明映射方法；真正下单前必须对**目标门店 + 当前 `orderType`** 重新 `query-meals` 取码，并以 `calculate-price` 返回为准。

## 1. 隐藏吃法词典

### 1.1 三类要素与处理方式

| 要素类型 | 例子 | 能否加购 | 处理方式 |
|---|---|---|---|
| **基础单品** | 薯条、麦乐鸡、苹果派、锡兰红茶 | ✅ | `query-meals` 取码 → `calculate-price` → `create-order` |
| **特调要求** | 走酱、去冰、少冰、换燕麦奶、加奶油球 | ✅（部分单品） | `query-meal-detail` 读 `modification` → 按 key 规则传参 |
| **免费配件** | 多要 2 包番茄酱 / 糖 / 胡椒粉 / 空杯 / 奶球 | ❌ **不是商品** | 外送单写 `remark`（≤50 字）；到店单给**到店话术** |

### 1.2 经典吃法 → MCP 映射（实测）

| # | 小红书爆款吃法 | 基础单品 | 特调（`modification`） | 免费配件（`remark` / 到店话术） |
|---|---|---|---|---|

| 12 | **无糖版任意套餐** | 任意套餐 | 套餐饮饮料换 **无糖可口可乐**（实测 **+¥0**，0 大卡） | 无 |

### 1.3 特调 key 传参规则（务必照做）

`query-meal-detail` 返回的 `modification.items[].values[]` 中，每项带 `selectedKey` 与（可能有）`unselectedKey`：

- **选中该项** → `key = selectedKey`
- **取消该项** → `key = unselectedKey`
- **该组内所有项都必须传入**（选中的用 `selectedKey`，未选中的用 `unselectedKey`），不能只传想改的那一个
- 某组 `minValues=1, maxValues=1` 且只有 1 项时，该项**必选，不能取消**，也不要向用户提供"不选"

**实例**（麦香鱼走酱，实测通过不报错）：

```json
{
  "productCode": "1600",
  "quantity": 1,
  "modification": {
    "values": [
      {"code": "100126", "key": "0-0", "quantity": 0},
      {"code": "100141", "key": "0-1", "quantity": 1}
    ]
  }
}
```

> ⚠️ `calculate-price` **不回显特调结果**（返回值里看不到"已去酱"），只能确认不报错。因此**不得向用户断言"特调已生效"**，话术用"已按你的要求传参，取餐时请核对一下"。

### 1.4 免费配件的 `remark` 写法

**硬边界**：`remark` 仅 `orderType=2`（外送）有意义，**最多 50 字**；到店自取（`orderType=1`）没有备注入口。

- **外送单** → 自动写入，示例：
  - `麦乐鸡薯条摇摇乐，请给2包胡椒粉、2包番茄酱、1包糖，多谢！`（27 字）
  - `港式奶茶做法：锡兰红茶请给2颗奶球，多谢！`（20 字）
- **到店单** → 给用户一句**到店话术**，例如："取餐时跟店员说'你好，想要 2 包胡椒粉和 1 包糖，谢谢'——到店单没有备注字段，我这边没法代填。"
- **不要写**：改价、退单、加量不减价、支付相关诉求（无效且占字数）。
- **字数优先**：超 50 字时优先保留"数量 + 品类"，省略客套。

## 2. 穷鬼套餐凑单演算算法

### 2.1 约束结构化

把用户的自然语言拆成：

| 类型 | 例子 | 处理 |
|---|---|---|
| **硬约束** | "不超过 20 块""必须有肉""无糖饮料" | 不满足直接淘汰，不作为"建议" |
| **软目标** | "越便宜越好""蛋白高一点" | 用于候选间排序 |
| **券条件** | "我有一张满 30 减 10" | 转成金额门槛，参与排序 |

### 2.2 枚举与验证流程

```
1. query-my-coupons + query-store-coupons + available-coupons   # 盘券（要领券先征得同意）
2. query-meals（当前 orderType）                                 # 取菜单与现价
3. 按硬约束筛出候选 2~5 个（优先套餐，套餐通常比单点叠加便宜）
4. 每个候选逐个送 calculate-price（用券传 couponId/couponCode）
5. 以返回值 price 排序，输出最低者 + 原价/实付对比
```

### 2.3 实测边界（2026-10-16）

- **到店单基本没有满减档位**：实测到店 ¥94 的篮子（巨无霸 + 麦香鸡 + 中薯条 + 麦乐鸡×2）返回 `discount:0`、无 `enjoyable`。满减主要出现在外送 / 团餐。
- **无档位就明说**：`calculate-price` 未返回 `enjoyable` / `balance` → 直接说"当前无凑单空间"，**不臆造档位**。
- **凑单建议必须自证**：建议加购小额单品跨档时，必须整体送 `calculate-price` 证明"加购后总支出 < 不加购总支出"，**征得同意才加入清单，绝不自动加购**。
- **外送单的跨档判定必须含配送费 + 打包费**：`deliveryPrice` + `packingPrice` 要计入总支出。
- **麦金卡随单购可能反向省钱**：实测加购 `521234 麦金卡体验卡（15 天）¥9.90` 后，指定商品降 ¥5、配送费与打包费归零。所以"凑单"时要把这张卡也作为一个候选分支参与比较。

### 2.4 麦金卡随单购判定式

对含 `withOrder: {membershipCode:"106", specId:"880"}` 且 `discountType="随单购麦金卡优惠"` 的商品（周边、麦金卡免配套餐等）：

```
方案 A（不加卡）：商品原价 + 配送费 + 打包费
方案 B（加卡）  ：商品麦金卡价 + 9.90（体验卡）+ 0 + 0
选 total 更小的一方；两者都送 calculate-price 实测，不心算
```

**实测样本**（外送 · 深圳金丰城 1421053，联名复古棒球帽）：

| 方案 | 构成 | 实付 |
|---|---|---|
| A 不加卡 | 39.90 + 6.00（配送） | ¥45.90 |
| B 加卡 | 34.90 + 9.90 + 0 + 0 | **¥44.80** |
| B + 巨无霸 | 34.90 + 29.00 + 9.90 + 0 + 0 | ¥73.80 |

### 3.3 组合判定

```
总热量 = Σ 各单品 energyKcal
总蛋白 = Σ 各单品 protein
```

**实测可用的达标组合**（"≤450 kcal 且蛋白 >25g"）：
- **双层吉士汉堡（429 / 27g）+ 无糖可口可乐（0）** = **429 kcal / 27g 蛋白** ✅ 两项都过
- 板烧鸡腿堡（391 / 23g）+ 无糖可口可乐 = 391 kcal / 23g —— 热量过、蛋白差 2g
- 蒜了吧黄油脆汁鸡-带骨里脊（126 / 19g）+ 吉士汉堡包（294 / 16g）= 420 kcal / 35g ✅

### 3.4 特调降卡与口径警告

可用 `modification` 做的降卡动作：
- **取消酱料**：巨无霸 `100116 巨无霸酱`、麦香鱼 `100126 麦香鱼酱`（price 0）
- **改冰量**：标准 / 去冰 / 多冰 / 少冰（不影响热量，影响口感）
- **换燕麦奶**：+¥2（`120146`，燕麦奶铁等）
- **换无糖饮料**：实测 **+¥0**

**口径警告（必须写进结论）**：
- 营养表是**标准份**数据，取消酱料能省的热量**不会自动反映** → 结论写"已去酱，实际热量略低于表中值"，给区间而非精确值。
- **套餐营养 ≠ 子项简单相加**（烹饪方式、份量差异）→ 标注"估算"。
- 表中有重复项（"小杯玉米杯""纯牛奶"各出现两次），数值一致，**不要当成不同商品**。
- 结论统一用"**约** XXX 大卡"。

## 4. 周边 / 联名抢货雷达

### 4.1 实测在售周边样本（2026-10-16）

| 编码 | 名称 | 原价 | 麦金卡价 | 门店 / 渠道 |
|---|---|---|---|---|
| `521954` | 麦当劳联名复古棒球帽 | 39.90 | 34.90 | 深圳金丰城 · 外送 |
| `521955` | 麦当劳联名徽章 | 39.90 | 34.90 | 深圳金丰城 · 外送 |
| `521743` | 薯条脆卜卜毛绒周边 | 29.90 | 24.90 | 深圳金丰城 · 外送 |
| `521946` | 旋旋星愿贴 | 3.90 | — | 上海陆家嘴 · 到店 |
| `521234` | 麦金卡体验卡（15 天） | 9.90 | — | 由 `withOrder` 自动带入 |

**周边随门店和渠道变化**：同一时刻，上海陆家嘴门店的**到店**菜单没有帽 / 徽章，深圳金丰城的**外送**菜单有。所以**必须先扫再下结论**，不能说"附近买不到"。

### 4.2 扫店流程

```
1. now-time-info
2. 取门店：query-nearby-stores（到店）或 delivery-query-addresses → delivery-query-stores（外送）
3. 对每个目标门店 query-meals，grep 目标周边编码 / 名称含"联名""限定""周边"
4. 汇总：哪家店、哪个渠道、什么价、是否带 withOrder
5. 用户选定 → calculate-price（带 withOrder 比较加卡与否）→ 确认 → create-order
```

### 4.3 三条做不到的（不得承诺）

1. **实时库存**：35 个工具里没有任何门店库存接口，"这家店还有几顶"无法回答。
2. **持续监控 / 补货提醒**：无法后台轮询。只能"问一次扫一次"，并明确这是**查询时点的在售状态**。
3. **积分商城换周边**：`mall-points-products` 类目 `2>8` 实测仅 3 项且全部过期（罗技键鼠 8-21、Nike Book 2 联名款 6-5、酸黄瓜吧唧 8-14）。

**给用户的替代建议**：想稳拿限量款，**直接下单锁单比监控更可靠**（MCP 侧锁单即生成真实订单）；若目标店当前不在售，可换 nearby 其他店或换外送渠道再扫。

## 5. 晒单卡片与文案模板

### 5.1 卡片结构（单文件 HTML / SVG，内联样式，无外部依赖）

```
┌────────────────────────────────────────┐
│ 麦当劳 · 今日神仙组合          ¥xx.x  │  ← 标题 + 实付（高亮）
├────────────────────────────────────────┤
│ [商品图] 双层吉士汉堡           ¥29.00 │  ← query-meals 的 image 字段可直接引用
│ [商品图] 无糖可口可乐           ¥11.00 │
├────────────────────────────────────────┤
│ 原价 ¥40.00   叠券/随单购后 ¥xx.x      │  ← 立省 ¥X 高亮
├────────────────────────────────────────┤
│ 热量 429 kcal │ 蛋白 27g │ 脂肪 22g    │  ← list-nutrition-foods
│ ▓▓▓▓▓░░░░  蛋白占比（柱状/环形）        │
├────────────────────────────────────────┤
│ "今天的麦当劳尊嘟太香了！..."           │  ← 文案
└────────────────────────────────────────┘
```

**数字红线**：价格必须来自 `calculate-price`；热量 / 营养必须来自 `list-nutrition-foods`；**没查过就不写**，不为好看编造。

## 6. 场景感应推送的可用维度

`now-time-info` 提供：`date / datetime / dayOfWeek / timezone`。据此可做：
